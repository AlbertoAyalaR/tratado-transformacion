## Dos capas

El programa no tiene cuatro activos en un plano. Tiene **dos capas de naturaleza distinta**.

### Capa de conocimiento
Método · Tratado · Programa de Validación

### Capa de realización
Instancias — MIRA es la primera

> **Consecuencia.** MIRA deja de ser *el producto del tratado* y pasa a ser *una instancia del tratado*. El marco teórico no depende conceptualmente de ella. Podrían existir instancias educativas, sanitarias, organizacionales o científicas sin modificar una línea del núcleo.

## El circuito

Cuatro relaciones, y **ninguna es del mismo tipo**. Confundirlas es el error que este tratado existe para evitar.

```
╔══════════════════ PROGRAMA DE VALIDACIÓN ══════════════════╗
║   gobierna cómo se recorre el circuito. No participa.      ║
║                                                             ║
║                      MÉTODO                                 ║
║                        │                                    ║
║                        │ CONSTRUYE                          ║
║                        ▼                                    ║
║                      TRATADO  ◄──────────────┐              ║
║                        │                     │              ║
║                        │ SE INSTANCIA EN     │ TENSIONA     ║
║                        ▼                     │              ║
║                     INSTANCIA                │              ║
║                        │                     │              ║
║                        │ EJECUTA             │              ║
║                        ▼                     │              ║
║                    OBSERVACIÓN ──────────────┘              ║
║                                                             ║
╚═════════════════════════════════════════════════════════════╝
```

| Relación | Tipo | Qué significa |
|---|---|---|
| Método → Tratado | **Construye** | El método organiza la producción de la teoría |
| Tratado → Instancia | **Se instancia en** | La instancia implementa la teoría; la teoría no la produce |
| Instancia → Observación | **Ejecuta** | La observación no brota de la instancia: resulta de una ejecución dentro de un diseño experimental |
| Observación → Tratado | **Tensiona** | No confirma ni valida: presiona. La teoría resiste o cede |

**Simetría de los metaobjetos.** La Constitución gobierna cómo se **construye** conocimiento. El Programa de Validación gobierna cómo se **contrasta**. Ninguno está en el flujo; ambos lo gobiernan.

## Autonomía epistemológica

> **Ningún activo justifica otro activo. Solo puede tensionarlo.**

Esta regla es la que impide las dos circularidades que un programa así atrae:

- ❌ *"La teoría es correcta porque el producto funciona."*
- ❌ *"El producto es correcto porque implementa la teoría."*

Ninguna vale. En concreto:

| | No justifica |
|---|---|
| El método | la teoría |
| La teoría | la instancia |
| La instancia | la teoría |
| La validación | el método |

Cada activo conserva su propio criterio de verdad. Lo único que pueden ejercer entre sí es **tensión**.

## Ciclos de vida

| Activo | Cambia sin arrastrar a los demás |
|---|---|
| **Método** | Sí. Puede construir otras teorías. |
| **Tratado** | Sí. Puede crecer sin tocar el método. |
| **Programa de Validación** | Sí. Puede durar años sin alterar la teoría. |
| **Instancia** | Sí. Evoluciona por razones propias: mercado, recursos, oportunidad. |

## Versionado

Cada activo versiona por su propio criterio. **No hay versión del programa completo.**

### Método
- **v1.0** — corroborado en dos construcciones independientes
- **v1.x** — reglas añadidas por experiencia, sin cambio de gramática
- **v2.0** — cambia la gramática: se añade, elimina o redefine un nivel

*Estado: v1.0.*

### Tratado
- **Nivel estabilizado** — la arquitectura no cambia; la expresión puede mejorar
- **Nivel cerrado** — arquitectura estabilizada + manuscrito editorial terminado
- **v1.0** — los tres niveles cerrados
- **v2.0** — la validación obligó a revisar la ontología

*Estado: N1 cerrado, N2 cerrado, N3 sin construir.*

### Programa de Validación
- **Diseñado** — especifica qué observar y qué refutaría qué
- **En ejecución** — recogiendo observación
- **Con resultados** — produjo tensión sobre el tratado

*Estado: diseñado, no iniciado.*

### Instancia
Versiona por sus reglas de producto. **No hereda la versión del tratado.**

## Criterios de cierre

**Un nivel del tratado cierra cuando:** la auditoría no modifica el mapa lógico · el manuscrito editorial está terminado · las decisiones están registradas.

**El método sube de versión cuando:** se construye un nivel completo bajo él · la auditoría posterior identifica reglas que faltaban o sobraban · **nunca durante la construcción, solo después**.

**El tratado se reabre cuando:** contradicción demostrada · cruce de niveles descubierto · el Programa de Validación produce una observación que refuta una afirmación.

*Nunca por una idea mejor.*

## Observación registrada — el nombre del Nivel 3

El Nivel 3 se llama **Diseño**. El nombre fue correcto mientras el proyecto era MIRA.

Su estatuto lógico real es más amplio: **lo contingente** — el espacio de libertad que queda tras la necesidad. *Diseño* es una instancia de ese espacio; también lo son gobernanza, implementación, política pública, producto, organización.

**No se cambia ahora.** Reabrir un nombre estabilizado sin necesidad viola la Constitución.

> **Regla para cuando se construya:** si el contenido rebasa naturalmente el concepto de diseño, no se fuerza el contenido para conservar el nombre. Se cambia el nombre para reflejar el estatuto lógico, no el vocabulario heredado.

*Precedente: en este programa, varias veces el cambio no vino de una idea nueva sino de que el nombre dejó de describir lo que ya existía.*
